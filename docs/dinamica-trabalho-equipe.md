
# VOLTA — Dinâmica de Trabalho da Equipe

## 1. Objetivo

Este documento apresenta a organização da equipe durante o desenvolvimento do projeto VOLTA, descrevendo a distribuição inicial das responsabilidades, as adaptações realizadas ao longo do projeto e os processos utilizados para acompanhar as atividades, comunicar decisões e integrar as entregas.

## 2. Distribuição inicial das responsabilidades

No início do projeto, os integrantes foram organizados em responsáveis primários e secundários para cada matéria. O responsável primário assumia a liderança das atividades daquela área, enquanto o secundário prestava apoio ao desenvolvimento.

| Matéria                                   | Responsável primário | Responsável secundário |
| ------------------------------------------ | ---------------------- | ------------------------ |
| Banco de Dados                             | Lucas Fabiano          | Gabriel Peotta           |
| Engenharia e Qualidade de Software (EQS)   | Davi Liu               | Enzo Herrera             |
| Desenvolvimento de Aplicativos Móveis     | Carlos Amaral          | Lucas Fabiano            |
| Desenvolvimento 2                          | Enzo Herrera           | Davi Liu                 |
| Desenvolvimento de Aplicações Dinâmicas | Breno Gomes            | Carlos Amaral            |
| Desenvolvimento de Operações Ágeis      | Enzo Herrera           | Davi Liu                 |
| Experiência do Usuário (UX)              | Breno Gomes            | Davi Liu                 |
| Modelagem de Dados                         | Lucas Fabiano          | Gabriel Peotta           |
| Business Intelligence (BI)                 | Gabriel Peotta         | Lucas Fabiano            |
| Inteligência Artificial (IA)              | Gabriel Peotta         | Lucas Fabiano            |

Em Engenharia e Qualidade de Software e Desenvolvimento de Aplicações Dinâmicas, foi estabelecido inicialmente que todos os integrantes participariam das atividades, independentemente da divisão entre responsáveis primários e secundários.

## 3. Adaptação das responsabilidades durante o projeto

Com o avanço do desenvolvimento, a equipe adaptou a divisão inicial para atender às necessidades técnicas do sistema e às demandas identificadas durante a implementação.

As principais mudanças foram:

- **Engenharia e Qualidade de Software (EQS):** Lucas Fabiano assumiu a maior parte das atividades da matéria, incluindo a documentação e as demais tarefas sob sua responsabilidade. Davi Liu concentrou sua participação na elaboração dos diagramas de EQS.
- **Experiência do Usuário (UX):** Davi Liu passou a atuar de forma mais intensa nessa área. Alguns membros como Gabriel Peotta auxiliaram em demandas como Pequisas (Quantitativa e Qualitativa), Teste A/B, Entre outras mais simples.
- **API relacionada ao Redis:** Enzo Herrera assumiu essa frente, que inicialmente estava prevista para Lucas Fabiano, com apoio de Gabriel Peotta.
- **Inteligência Artificial e MongoDB:** Gabriel Peotta assumiu a API do MongoDB utilizada pelo chatbot, incluindo o trabalho relacionado ao armazenamento de dados conversacionais. Essa mudança alterou a divisão inicialmente prevista para a participação de Lucas Fabiano nessa frente.

Essas mudanças demonstram que a distribuição inicial funcionou como uma orientação, permitindo que as responsabilidades fossem ajustadas conforme as necessidades do projeto.

## 4. Organização e acompanhamento do trabalho

A equipe utiliza o Jira como ferramenta principal para organizar e acompanhar as atividades. As tarefas são atualizadas conforme o trabalho é realizado, permitindo visualizar o andamento das entregas e identificar pendências.

No início do projeto, o GitHub Projects também foi utilizado como ferramenta complementar para o planejamento e a organização das atividades.

Para o desenvolvimento colaborativo, os integrantes trabalham em seus respectivos repositórios e abrem Pull Requests (PRs) para apresentar suas alterações. Os PRs passam pela aprovação dos integrantes antes da integração das mudanças. Todos os integrantes participaram das aprovações, contribuindo para a revisão do código e para a colaboração entre as diferentes frentes de desenvolvimento.

## 5. Comunicação e colaboração

A comunicação da equipe ocorre principalmente pelo WhatsApp, utilizado para compartilhar mensagens relacionadas ao projeto, alinhar atividades e conversar sobre as demandas do VOLTA e do projeto do primeiro ano.

Além da comunicação por mensagens, a equipe já realizou reuniões presenciais para discutir o andamento do trabalho, esclarecer dúvidas e alinhar decisões.

A combinação entre comunicação direta, acompanhamento das tarefas no Jira e revisão das alterações por meio de Pull Requests contribui para a coordenação das atividades e para a integração das entregas.

## 6. Sprint atual e planejamento das etapas finais

A sprint atual está em andamento, com início em **14 de outubro de 2026** e prazo de término em **20 de outubro de 2026**.

Durante esse período, a equipe busca concluir as atividades previstas e organizar as entregas para a etapa final do projeto.

A meta interna é finalizar as pendências até 20 de outubro e reservar o período de **21 a 27 de outubro de 2026** para testes, correções, integração e revisão. Está prevista uma nova sprint para essa etapa, podendo ser organizadas sprints adicionais conforme a necessidade e a orientação da professora.

Entre as atividades finais estão a validação das APIs, a verificação do armazenamento de dados, os testes das funcionalidades, a revisão da documentação e a conferência das evidências necessárias para a apresentação do projeto.

A entrega oficial está prevista para **27 de outubro de 2026**.

## 7. Considerações finais

A dinâmica de trabalho do VOLTA combina uma divisão inicial de responsabilidades com a adaptação das atividades ao longo do desenvolvimento. O acompanhamento pelo Jira, a comunicação pelo WhatsApp, as reuniões presenciais e a revisão colaborativa por meio de Pull Requests fazem parte da organização adotada pela equipe.

A flexibilidade na distribuição das responsabilidades permitiu que os integrantes ampliassem ou modificassem sua participação em determinadas áreas conforme as necessidades do projeto. Essa organização contribui para o acompanhamento das entregas e para a preparação do sistema para a etapa final de testes e revisão.
